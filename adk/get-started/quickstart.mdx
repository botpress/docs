This guide walks you through creating your first agent, running it locally, and deploying it to Botpress Cloud.

<Info>
  Before you start, [install the ADK CLI](/adk/get-started/install) and sign in to your [Botpress account](https://sso.botpress.cloud).
</Info>

## Create an agent

Run the init command and pass a name for your project:

```bash
adk init my-agent
```

The CLI walks you through a short wizard. First, pick the `hello-world` template to start with a working agent:

```txt
 ▄▀█ █▀▄ █▄▀  Botpress ADK
 █▀█ █▄▀ █░█  Initialize New Agent

 Step 1 of 2

Select a template:

› blank
    Empty project with just the folder structure

  hello-world
    A working chatbot with chat and webchat integrations

  slack-triage
    Slack bot that monitors a channel, classifies requests, and routes to the right person

  knowledge-assistant
    RAG-powered Q&A agent with knowledge base and source citations

  crm-enrichment
    Scheduled workflow that enriches CRM contacts with AI-driven classification
```

Then pick a package manager. The wizard only shows the ones already installed on your machine:

```txt
 ▄▀█ █▀▄ █▄▀  Botpress ADK
 █▀█ █▄▀ █░█  Initialize New Agent

 Step 2 of 2

Select a package manager:

● Bun
    Install with bun
○ pnpm
    Install with pnpm
○ Yarn (not installed)
○ npm
    Install with npm
```

The CLI creates the `my-agent` directory, installs dependencies, and runs any setup commands the template needs (for `hello-world`, that's installing the `chat` and `webchat` integrations). If you're signed in, it also prompts you to link the project to a workspace so you can deploy later without re-authenticating:

```txt
Linking to Botpress — connect your agent to a workspace and bot for deployment.

📋 Select a workspace (type to search):

› jacksonyu's Workspace
  ...

✅ Successfully linked local agent to remote bot!
Bot: my-agent
Workspace: jacksonyu's Workspace
```

Move into the project directory:

```bash
cd my-agent
```

<Tip>
  To skip the wizard, pass `--template` and `--yes`: `adk init my-agent --template hello-world --yes`.
</Tip>

## What's in your project

Every ADK project follows the same layout. `agent.config.ts` at the root defines models, persistent state, and which integrations your agent uses. Each folder under `src/` holds one kind of building block:

<Tree>
  <Tree.Folder name="my-agent" defaultOpen>
    <Tree.File name="agent.config.ts" />
    <Tree.Folder name="src" defaultOpen>
      <Tree.Folder name="actions" />
      <Tree.Folder name="conversations" />
      <Tree.Folder name="knowledge" />
      <Tree.Folder name="tables" />
      <Tree.Folder name="triggers" />
      <Tree.Folder name="workflows" />
    </Tree.Folder>
    <Tree.File name="package.json" />
    <Tree.File name="tsconfig.json" />
  </Tree.Folder>
</Tree>

The `hello-world` template ships with a single conversation handler at `src/conversations/index.ts`:

```typescript
import { Conversation } from '@botpress/runtime'

export default new Conversation({
  channel: '*',
  handler: async ({ execute }) => {
    await execute({
      instructions: `You are a helpful AI assistant built with Botpress ADK. You can assist users with their questions and tasks.`,
    })
  },
})
```

Edit the `instructions` string to change how your agent behaves.

## Run your agent locally

Start the development server:

```bash
adk dev
```

`adk dev` does a few things at once:

- Generates TypeScript types for your installed integrations so your editor knows their shapes
- Builds the agent into a local runtime
- Starts the dev server on port `3000` and the Control Panel on port `3001`
- Watches your files and rebuilds on every save

Once it's running, open the Control Panel at [http://localhost:3001](http://localhost:3001). You can browse conversations, inspect Workflows and tables, manage integration settings, and chat with your agent from the built-in Chat view.

```bash
adk chat
```

## Deploy to Botpress Cloud

When you're ready to ship your agent, run:

```bash
adk deploy
```

This builds a production bundle and uploads it to the workspace you linked during `adk init`. If you skipped the linking step, run `adk login` followed by `adk link` before deploying.

<Check>
  You've shipped your first agent with the ADK.
</Check>
